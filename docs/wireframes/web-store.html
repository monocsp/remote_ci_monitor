웹 스토어 탭 — 심사까지만, 출시는 사람

큐 화면 옆의 두 번째 탭. 소비 저장소(dolomood-app-renew)의 scripts/release/* 와 rcm 프리셋(release-plan · gate-smoke · scenario-qa · release-upload · release-review)이 이미 하는 일을 버튼으로 옮긴다. 판정은 전부 소비 레포 스크립트가 하고 웹은 그 JSON 을 그린다. 값은 2026-09-15 첫 실측(1.0.0-180)의 다음 회차를 가정했다. 번호는 기획 항목, 마우스를 올리면 서로 강조된다.

1 기획 항목 번호 요소를 가리키는 선UI 문자열은 영어(제품 규칙 · ko 는 i18n.js), 설명은 한국어값은 예시 저장소(dolomood)의 실측 — rcm 은 저장소를 모른다(9절)

v0.4 (2026-09-17) — 도는 중인 Build·upload 행을 세 층으로(46~48): 가로로 긴 막대 → «지금 하는 일» 한 줄 → 펼치면 항목 목록(끝남 초록 · 도는 중 파랑 화살표 · 기다림 회색). 행 머리와 접힌 상태도 옅은 파랑(49). 진행 마커 문법을 ::rcm::progress::done/total::단위::상태 로 확정하고(소비 레포 쪽은 feat/rcm-progress-markers 브랜치에 실제로 찍어 두었다), 9절에 «다른 저장소를 붙이는 법» 을 두어 rcm 이 범용임을 문장으로 잠갔다. v0.3 (2026-09-17) — 도는 중인 Build·upload 행에 잡 카드 둘(43~45): 스모크는 시간 근거 막대 + 스텝, 시나리오 QA 는 청크 격자 + 2단계 캡처 필름. v0.2 (2026-09-17 오너 피드백) — 화면의 뼈대를 바꿨다. 위쪽은 접히는 가로행 넷(설정 · 소스 · 빌드/업로드 · 스토어): 다 되어 있으면 옅은 초록으로 접힘, 안 되어 있으면 옅은 빨강으로 펼쳐짐. 접힌 머리에는 필수값만, 펼치면 상세. 아래 본체는 「이번 버전이 스토어에 어떻게 올라가나」 — App Store Connect 의 버전 제출 화면을 본떠 소개 이미지 · 버전 · 빌드 · 릴리스 노트 · 심사 정보를 한 페이지에, Google Play 도 같은 배치로 나란히(보기만). 다 설정돼 있으면 이 본체가 펼쳐져 있고, 접으면 머리에 버전 · 빌드번호 · 「App Store + Google Play 로 올린다」 만 남는다. 9절의 질문 여섯은 오너가 추천대로 결정했다.

도는 중인 scenario-qa 카드 — 청크 격자

보여주는 것
청크 done/total 막대(근거 steps · 정확) · 플랫폼별 레인에 청크 한 칸씩(초록 ✓ · 빨강 ✗ · 파랑 ▶ · 회색 미실행 · 빗금 skip) · 지금 도는 청크와 경과/중앙값 · 실패 목록.
데이터

규칙

7. 이 화면이 정한 규칙

  • 행의 색이 곧 상태다. 접히는 행 넷은 «다 됨 → 옅은 초록 · 접힘», «안 됨 → 옅은 빨강 · 펼침», «도는 중 → 파랑 · 펼침», «낡음 → 황토 · 펼침», «해당 없음 → 회색 · 접힘». 접힌 머리에는 필수값만(버전 · N · 상태 · 나이), 펼치면 상세. 사람이 여닫은 것은 기억한다.
  • 본체는 「스토어에 어떻게 올라가나」 한 페이지. App Store Connect 의 버전 페이지 순서(스크린샷 → 버전 정보 → What's New → 빌드 → 심사 정보)를 그대로 쓰고, Google Play 를 같은 그룹 순서·같은 줄 위치로 옆에 둔다. 없는 필드는 비워 두고 이유를 쓴다. 전부 읽기 전용 — 정본은 git.
  • 본체의 기본은 펼침. 네 행이 초록이면 펼쳐져 있고, 하나라도 빨강이면 접히며 필이 이유를 말한다. 접힌 머리 = 버전 · 빌드번호 · «App Store + Google Play».
  • 웹은 판정하지 않는다. N · 스테이지 · 심사 판정 · 위반은 소비 레포 스크립트의 JSON·종료코드 그대로. rcm 코드에 dolomood 이름은 없다 — 전부 프로파일.
  • 세 번의 타이핑. S2 · S7 직전 · 심사 제출 직전에 N 을 새로 타이핑한다.
  • 출시 버튼 없음. «Release · Publish · Rollout» 은 어떤 상태에서도 없다. 고정 문장은 본체 바닥과 결과에. 관리형 게시 필은 절대 초록이 되지 않는다.
  • 관문이 먼저. 민감 값은 설정 화면에서 드롭/경로로 다 넣은 뒤에야 스토어 화면이 열린다. 안에서는 비밀을 묻지 않는다. API 는 present · fingerprint · verified_at 만.
  • 권한. 보기 → 잡 제출 → admin. 비활성 버튼은 이유를 쓴다.
  • 실패 ≠ 빈 값 ≠ 모름 ≠ 낡음. 각각 다른 색·모양. 업로드가 «모름» 이면 재제출 버튼이 없다.
  • 도는 행은 세 층. 긴 막대(근거 글자와 함께) → «지금 하는 일» 한 줄 → 펼치면 항목 목록(✓ 초록 · ▶ 파랑 · 회색 waiting). 행 머리와 접힌 상태는 옅은 파랑.
  • 진행은 근거를 말한다. 막대의 근거는 셋 중 하나 — 선언된 스텝 수 · 세부 진행 마커(::rcm::progress::) · 측정 시간. 근거를 화면에 쓴다(«by time · median 21m»). 숫자를 지어내지 않는다: 잡이 총수를 선언하지 않으면 «of ~54» 처럼 추정임을 표시한다.
  • 큐 화면 규칙을 물려받는다. 시각·소요 표기, 색 + 글리프 + 테두리, 키보드·보조기기, SSE, i18n.

8. 다른 저장소를 붙이는 법 — rcm 은 저장소를 모른다

이 목업의 값은 전부 예시 저장소(dolomood)의 실측이지만, rcm 코드·스키마·문구 어디에도 그 이름은 없다. 어떤 프로젝트든 아래 넷을 주면 같은 탭이 뜬다. 하나가 없으면 그 카드가 «not configured — profile.presets.qa is empty» 로 비고, 나머지는 그대로 돈다.

  • ① 프로파일 — server.toml 의 [repos.<name>.release]: 어떤 비밀이 필요한지(secrets · secret_files), 그 폴더를 잡에 무슨 이름으로 넘길지(secrets_dir_env), 역할별 프리셋 이름(presets = {plan, gate, qa, upload, review}), 회차 드라이버(driver), 브랜치·태그 규칙, 빌드번호 정책. 설정 화면(4절)의 행과 관문의 «n of m» 은 여기서만 나온다.
  • ② 프리셋 역할과 산출물 계약 — rcm 은 판정하지 않고 파일을 그린다. 역할마다 rcm 이 읽는 최소 필드를 rcm 문서(docs/release-contract.md)가 정한다: plan.json {n, first_release, store, blockers[], warnings[], measured_at} · report.json {verdict, platforms} · upload.json {status, n, platforms} · review-plan.json {ios, android, plan_verdict, listing{preview,diff}} · review.json {overall_status, platforms, observed}. 없는 필드는 —. 판정 어휘는 프로젝트의 것을 그대로 필에 쓴다 — rcm 은 ready · already_submitted · *_unreadable 몇 개만 색으로 안다(나머지는 빨강).
  • ③ 마커 — 스텝(::rcm::step::) · 스텝 총수(::rcm::steps::N, 아는 경우만) · 스텝 안 진행(::rcm::progress::done/total::unit::state). 이것만으로 46~48 의 세 층이 선다. 찍지 않으면 시간 근거 막대와 로그 tail.
  • ④ 소개 자료 규약 — store/ 비슷한 폴더가 있으면 프로파일 listing = {preview_cmd, diff_cmd, validate_cmd, screenshots_glob} 로 명령을 가리킨다. 없으면 본체의 두 스토어 절은 «no listing command in profile» 로 접힌다.
  • 하지 않는 것 — rcm 에 특정 앱의 스크립트 경로·키 이름·심사 데모 계정 필드 이름을 박지 않는다. 예시는 examples/server.toml 의 한 프로파일과 README 한 절뿐이다. 이 목업의 «dolomood» 는 그 예시 프로파일의 이름이다.
