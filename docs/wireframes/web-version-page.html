1. 요구사항 명세

소유자의 말(2026-09-18)을 항목으로 나누고 번호를 붙였다. 뒤의 모든 절은 이 번호를 가리킨다.

#요구출처(소유자의 말)받아들인 해석
R1«새 버전 만들기»가 흐름의 시작이다「앱스토어에서는 새로운버전만들기 하고 거기서 수정을 진행하는데 우리도 그게 맞겠어」스토어 탭의 첫 화면은 버전 목록이고, 편집·심사는 «버전 페이지» 안에서만 한다.
R2웹 버튼 · rcm CLI · 스킬 호출, 세 입구가 같은 흐름「이 웹페이지에서 버전 만들기 하거나 rcm에서 버전을 올린다고 새로운버전으로 release 배포 스킬호출하면」웹 «새 버전 만들기», rcm release new, /rcm-release-driver 스킬 모두 같은 서버 API 를 부른다.
R3«새 버전이 만들어진다»고 먼저 알리고, 버전만 묻는다「새로운 버전이 만들어진다 라고 알리고, 몇버전 만드는지만 묻고」대화상자 하나. 다른 입력(트랙 · dry-run · 빌드 번호)은 묻지 않는다.
R4iOS · Android 힌트를 따로, 각 스토어의 현재 버전 + patch「안드가 1.0.0이고 애플이 1.1.0인 유저가 있을 수 있으므로 따로 1.0.1, 1.1.1 로 힌트」플랜이 읽은 App Store 라이브 버전과 Play 프로덕션 버전 이름을 각각 patch+1 해서 미리 채운다. 둘 다 고칠 수 있고, 한쪽만 만들 수도 있다.
R5아무것도 안 하면 삭제된다「아무것도 안 누르거나 rcm에서 다른말이 없으면 삭제하게 된다」만든 뒤 편집도 제출도 없이 시간이 지나면 드래프트를 지운다(스토어 쪽 draft version 포함, 9절 Q2).
R6버전 페이지의 필드는 이전 버전 값으로 미리 채워진다「텍스트필드들이 이전버전에 있던걸 채워서 보여주도록 해 그러면 유저가 설정하거나 그대로 올리거나」지금 «심사 패널»이 읽기 전용으로 보여 주던 자리를 편집 가능한 필드로 바꾸고, 라이브 버전(또는 store/ 파일)의 값으로 채운다. 그대로 두면 그대로 올라간다.
R7rcm 은 터미널(프로젝트 스크립트)을 웹으로 그리는 방식을 유지한다「rcm도 이런식으로 되게 해야해 어쨋든 터미널에 연결된걸 지금 웹으로 비주얼 그리는형식이니」스토어에 쓰는 것은 계속 프로젝트 스크립트다. rcm 은 편집한 값을 파일로 넘기고 결과 JSON 을 그린다.
R8전체 진행 막대 · 진행 정도 · «버전 빌드 중» 표시는 바텀시트로「전체 프로그레스바나 진행정도 그리고 버전빌드중 등은 바텀시트로 옮기자」맨 위 큰 막대(0.3.2)는 없애고 바텀시트 머리로 옮긴다.
R9바텀시트에 심사 제출 버튼「거기에 심사제출버튼도 만들고」제출 버튼은 바텀시트에만 있다. 본문에는 없다.
R10바텀시트는 버전 페이지에만 있다「바텀시트는 위에 말한 버전생성이 되는 페이지에 바텀시트생기게 하고」버전 목록 화면 · 설정 화면에는 없다.
R11접힌 머리 = 심사 전에 필요한 것들; 제출 가능하면 제출 버튼「원래는 접어져서 헤드에 심사넣기전에 필요한것들 보여주다가 심사넣을 수 있으면 심사제출버튼도 있고」머리 한 줄에 «남은 것 n개 · 첫 항목» 또는 «제출 준비됨» + 버튼.
R12펼치면 이전 버전과 달라진 점, 못 올리면 누락 목록「확대 버튼하면 바텀시트가 커지며 이전버전과 달라진점 보여지고 심사 올리지 못 하면 누락된거 보여주게 해」펼침 = 전체 진행 + 단계 + 변경 diff + 누락 체크리스트(각 항목이 고치는 곳으로 가는 링크).

3. 개념 모델 — «버전(드래프트)»

rcm 에 버전이라는 객체가 처음 생긴다. 지금까지 rcm 은 «잡»과 «드라이버 실행»만 알았고 버전은 플랜의 build_name 문자열이었다.

iOS (App Store Connect)

ASC 에는 실제로 «버전» 객체가 있다(appStoreVersions, 상태 PREPARE_FOR_SUBMISSION …). 새 버전 만들기 = ASC 에 draft version 생성. 문안(appStoreVersionLocalizations)은 버전에 붙는다. 삭제 API 도 있다.

따라서 R1·R5 가 그대로 대응된다: 만들기 → 편집 → 제출, 방치하면 draft 삭제.

Android (Google Play)

Play 에는 «버전 객체»가 없다. 스토어 등록정보는 앱에 하나(edit 트랜잭션), 릴리스는 트랙에 붙고 이름(versionName)은 업로드한 번들이 정한다.

따라서 Android 의 «버전»은 rcm 안의 드래프트일 뿐이다: 버전 이름 + 편집한 등록정보 + 릴리스 노트를 들고 있다가 업로드·제출 때 스크립트가 edit 로 반영한다. 삭제 = rcm 드래프트만 지우면 된다(스토어에는 아직 아무것도 없다).

드래프트의 수명

만듦 — 대화상자에서 iOS/Android 버전 이름을 정하면 rcm 이 versions 행을 만들고, 역할 version 프리셋을 mode=create 로 돌린다. iOS 는 스크립트가 ASC 에 draft 를 만들고 version.json 에 asc_version_id 를 적는다.
프리필 — 같은 잡이 이전 버전(라이브)의 문안을 읽어 prefill.json 으로 낸다. rcm 은 그것을 편집 가능한 필드로 그린다. 스크립트가 못 읽으면 store/ 파일(listing.preview)로 대신 채우고 «파일에서» 라고 표시한다.
편집 — 사람이 웹에서 고친다. rcm 은 versions.edited_json 에 저장하고 «바뀜» 칩을 단다. 저장은 즉시(자동), 스토어에는 아직 아무것도 쓰지 않는다.
빌드 · 업로드 · 심사 — 기존 흐름 그대로. 다만 review/upload 잡에 listing.json(편집본)을 파일 입력으로 넘긴다. 스크립트가 그것을 ASC 버전 문안 / Play edit 에 쓴다.
끝 — 심사 제출 성공(review.json overall_status=submitted)이면 드래프트는 «제출됨»으로 닫힌다. 스토어 승인 뒤 출시는 여전히 사람이 콘솔에서.
폐기 — 편집도 잡도 없이 TTL(기본 24시간, 9절 Q1)이 지나면 청소기가 version 프리셋을 mode=delete 로 돌려 ASC draft 를 지우고 행을 «폐기됨»으로 둔다. 사람이 «버리기»를 눌러도 같다. 편집한 흔적이 있으면 자동 삭제하지 않고 만료 경고만 낸다(Q2).

4. rcm ↔ 프로젝트 계약 변경 — 스킬에 전달할 것

rcm 은 특정 프로젝트를 모른다는 규칙은 그대로다. 아래는 docs/release-contract.md 에 더해질 내용이고, 각 항목이 어느 스킬 템플릿을 바꾸는지 적었다.

4.1 새 역할 version (선택이지만 «새 버전 만들기»를 쓰려면 필수)

역할rcm 이 보내는 입력rcm 이 읽는 산출물종료 코드스킬
versionmode = create|delete|prefill · ios_version · android_version(빈 값이면 그 스토어는 만들지 않음) · asc_version_id(delete 때)version.json · prefill.json0 · 1 실패 · 2 환경 · 3 이미 있음(같은 이름의 편집 중 버전) · 4 삭제 불가(제출된 버전)rcm-store-connect 에 release_version.sh 템플릿 추가
// version.json — mode=create 뒤
{ "schema": 1, "ios": { "version": "1.1.1", "asc_version_id": "abc123", "state": "PREPARE_FOR_SUBMISSION" },
  "android": { "version": "1.0.1", "note": "draft lives in rcm until upload" }, "measured_at": "…" }

// prefill.json — 이전 버전의 문안(라이브) — 필드 이름은 review 계약의 listing 과 같다
{ "schema": 1, "source": "asc_live:1.1.0 · play_listing",
  "ios": { "subtitle": "…", "promotional_text": "", "description": "…", "keywords": "…", "support_url": "…", "marketing_url": "…", "whats_new": "…",
           "screenshots": [ { "path": "store/screenshots/ios/ko/0_APP_IPHONE_65_0.png" } ] },
  "android": { "title": "…", "short_description": "…", "full_description": "…", "whats_new": "…", "graphics": [ … ] } }

4.2 plan.json 에 힌트 두 개(R4)

"store": { "asc_live": "1.1.0", "asc_editing": null, "play": { "production": 180, "production_name": "1.0.0" } },
"next_version_hint": { "ios": "1.1.1", "android": "1.0.1" }      // 없으면 rcm 이 asc_live · production_name 에서 patch+1 로 계산

스크립트가 힌트를 주지 않아도 rcm 이 asc_live 와 play.production_name 에서 계산한다. 계산 규칙은 «마지막 숫자 +1»뿐이고, 사람이 고칠 수 있다.

4.3 review · upload 에 편집본 전달(R6 · R7)

입력 listing_file(경로)을 추가한다. rcm 이 워크스페이스에 listing.json 을 써 두고 그 경로를 넘긴다. 파일이 없거나 listing = notes-only 면 지금처럼 store/ 파일만 쓴다. 스크립트는 파일이 있으면 그 값이 store/ 보다 우선이다. 심사 플랜(mode=plan)도 같은 파일을 받아 «이 값으로 올라간다»를 review-plan.json.listing.preview 로 되돌려 준다 — 바텀시트의 diff 는 이것과 prefill.json 을 비교한 것이다.

4.4 드라이버(선택)에 «V» 단계

rcm-release-driver 의 S0 앞에 V 버전 만들기가 붙는다. 드라이버는 --version-id <rcm id> 를 받고, 없으면 지금처럼 --build-name 만으로 돈다(호환). 스킬 호출(R2)은 «새 버전을 만듭니다 — 어느 버전?»만 묻고 나머지는 서버 API 를 부른다.

8. 안전 규칙 — 유지되는 것과 새로 생기는 것

유지: release · publish · rollout 버튼 없음 · 관리형 게시는 제출마다 사람이 체크 · 빌드 번호는 플랜의 n 만(자동/직접 토글) · 비밀은 서버에만 · unsafe_release_type 빨간 띠.
새로: 드래프트 자동 삭제는 되돌릴 수 없는 일이다(ASC draft 삭제). 그래서 (1) 편집이 있으면 자동 삭제하지 않는다 (2) 삭제 잡의 로그가 남는다 (3) 제출된 버전은 절대 삭제 대상이 아니다 (4) 이름이 라이브보다 작은 버전은 만들지 않는다.
주의: 편집 가능한 필드가 생기면 «웹에서 고친 값이 store/ 파일과 달라지는» 상태가 생긴다. 이 문서의 답은 파일이 원본이 아니라 드래프트가 원본(제출 때 스크립트가 store/ 로 되쓰고 커밋할지는 Q4)이다.

9. 결정이 필요한 것

Q1 드래프트 TTL 기본 24시간으로 잡았다. 12h · 48h · 프로파일 키(version_ttl_hours)로 조정 가능하게 둘지.
Q2 편집한 드래프트도 자동 삭제할지 초안은 «편집이 있으면 경고만, 사람이 버리기». 소유자의 말 «아무것도 안 누르거나»를 넓게 읽으면 편집했더라도 제출 없이 방치하면 삭제. 어느 쪽?
Q3 Android 의 «버전» Play 에는 객체가 없으므로 rcm 드래프트 + 업로드 때 반영으로 잡았다. 이름 힌트는 production 의 versionName 기준. 괜찮은지.
Q4 편집한 문안의 최종 저장소 (a) 스토어에만 쓰고 끝, (b) 제출 때 스크립트가 store/ 에 되써서 «chore(store): 문안 1.1.1» 커밋을 PR 로, (c) 둘 다. dolomood 의 «store/ 가 단일 원본» 규칙(AGENTS.md)을 지키려면 (b)나 (c).
Q5 기존 행 넷의 거취 «상태 띠» 한 줄로 접고 자세히에서 펼치는 안. 아예 없애고 바텀시트 누락 목록에 흡수할 수도 있다.
Q6 맨 위 큰 막대 R8 대로 바텀시트로 옮기면서 없앤다. 버전 목록 화면에서 회차가 돌 때는 드래프트 행의 «진행 중» 필로만 보인다. 괜찮은지.
