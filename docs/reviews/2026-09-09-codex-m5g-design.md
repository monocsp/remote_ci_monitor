```

server.py(App.artifact_storage · health · 라우트) · worker.py 와 remote_worker.py 의 워크스페이스 정리 ·
docs/m5f-workplan.md(같은 형식의 앞선 명세) · docs/m5e-workplan.md §7~§10(산출물 보존의 선례).

남긴다. 하루 비성공 잡 50개, 여유 628 GiB.

이 명세가 정한 것: ① 증거(로그 14/30일)와 부피(워크스페이스 + 그 잡의 tree.tar.gz, 새 키
workspace_retention_days = 1)를 다른 시계로 재운다 ② 날짜와 무관한 workspace_storage_max_bytes

 1. 안전성 — 「증거는 안 지운다」와 「못 재면 예산·바닥을 건너뛴다」가 실제로 fail-closed 인가.
 2. 「한 회차에 한 번만 계획한다」가 바닥 규칙을 무력하게 만드는 경우가 있나.
 3. 후보를 DB 가 아니라 workspaces/ 스캔에서 얻는 것 — 경합·TOCTOU.
 4. 측정 캐시 · st_blocks × 512 · 하드링크 이중 계수.

10. 테스트 배치와 mutcheck 2종이 안전 성질을 실제로 잠그나.
```

## 2. 끊기기 전에 낸 관찰과 반영

| # | 코덱스가 한 말(원문) | 판단 | 반영 |
|---|---|---|---|
| A | 「현재 `main` 쪽 코드에는 이미 M5f/M5e 변경이 들어와 있어, M5g 명세의 line 참조가 일부 오래된 상태인지 별도로 봐야 합니다」 | 맞다 | 이미 처리됐다 — dev(#66 admission 머지) 로 올린 뒤 명세의 `file:line` 15개를 스크립트로 전수 대조해 고쳤다. 지금은 전부 일치한다 |
| B | 「`artifact_storage()` 의 `last_sweep_at` 버그는 명세 주장과 코드가 일치합니다」 | 확인 | §3.1 A · §13 A 그대로. PR 2 에서 고친다 |
| C | 「`tree.tar.gz` 는 서버가 원격 워커에게 입력 스냅샷을 줄 때도 읽지만, 그 경로는 claim 된 **활성** 잡의 워커 API 입니다. 따라서 「종료된 잡에서 아무도 읽지 않는다」는 **좁은 명제는 맞고**, 명세도 그 표현을 유지하는 게 중요합니다」 | 확인 | 결정 51 의 근거가 유지된다. 표현을 넓히지 않았다 |
| D | 「M5g 예산은 서버 `data_dir` 만 지우므로 「원격 워커 잡」을 후보에서 빼는 설계는 맞지만, **서버에 남는 입력 tar 과 워커 로컬 워크스페이스를 서로 다른 문제로 분리해** 써야 합니다」 | **명세의 구멍이었다** | §4.4 에 넣었다 — 두 스캔(`workspaces/`·`jobs/`)은 **독립**이다. 워크스페이스 목록에만 기대면 원격 잡의 서버 쪽 tar 이 부피 규칙을 통째로 비껴가 로그 시계(30일)를 탄다. `--no-cache` 원격 풀에서 512 MB × 잡 수가 조용히 쌓인다 |
| E | 「고아 디렉터리를 「총량에는 넣고 지우지 않는다」는 부분은 **예산/바닥 계산을 영구적으로 막을 수 있어서**, 명세가 그 상태의 표시와 실패 등급을 더 엄격히 정해야 합니다」 | **맞다. 더 나쁜 결과가 있었다** | §4.3 에 규칙을 새로 넣었다 — 지울 수 없는 바이트(도는 잡 + 고아)만으로 예산을 넘으면 **예산 규칙은 아무것도 안 고른다**(`budget_unreachable`). 안 그러면 못 이룰 목표를 위해 매 sweep 마다 종료 잡 워크스페이스를 전부 태운다. **바닥 규칙은 그래도 돈다** — 회계가 아니라 응급이고 지운 바이트만큼 실제로 여유가 는다. `rcm check` 가 원인을 지목한다 |
| F | 「「나이 규칙은 크기 측정 실패와 무관하게 돈다」는 안전 방향이지만 용어가 헷갈립니다. **압박 삭제는 fail-closed, 나이 삭제는 정상 삭제**라서 둘을 같은 「못 재면 안 지운다」 문장 아래 두면 **구현자가 잘못 잠글 수 있습니다**」 | 맞다 | §4.3 과 결정 55 의 제목을 「못 재면 **압박 삭제만** 멈춘다」로 바꾸고, 잘못 잠갔을 때의 결과(「디스크가 차는 동안 나이 규칙까지 멈춘다 — 이 마일스톤이 고치려던 그 상태」)를 명시했다 |
| G | 「측정 캐시는 성능상 필요하지만 「종료 잡은 다시 안 변한다」는 전제에 기대는 부분이 가장 약합니다. 워커가 놓친 백그라운드 프로세스나 사람이 직접 만진 디렉터리는 예산 숫자를 틀리게 만들 수 있으므로, **캐시의 불변 조건과 무효화 조건을 더 써야** 합니다」 | 맞다 | §4.4 를 고쳤다 — 캐시는 `(bytes, 최상위 st_mtime_ns)` 이고 매 sweep `lstat` 한 번으로 확인한 뒤 쓴다. 메모리에만 있고 재시작하면 다시 잰다. 안쪽 파일만 바뀌어 최상위 mtime 이 안 변하는 경우는 **받아들이고** 그 대신 `measured_at` 을 화면에 싣는다고 적었다 |
