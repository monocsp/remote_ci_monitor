## B. 고쳐야 할 것

P0·P1 없음.

### P2

- **B-1. 빈 값의 의미가 CLI 와 다르다.** 가드 438~439행 `data = env.get(…) or os.environ.get(…)` / `if data:` 는 `RCM_SERVER_DATA_DIR=` (빈 문자열)를 「없음」으로 본다. CLI 의 `_env_overrides` 371행은 `if env_key in os.environ` 이라 빈 문자열도 적용해 `data_dir = ""` → `Path("").expanduser()` = `.` → **현재 디렉터리에 `rcm.sqlite3` 를 만든다**. 재현(일회용 venv, 시험 설정): `RCM_SERVER_DATA_DIR= rcm token --config server.toml list` → 설정의 `data_dir` 이 아니라 cwd 에 새 DB 가 생기고 빈 목록을 찍는다(확인 — 스크래치 디렉터리에 `rcm.sqlite3` 135 KB 생성). 가드는 설정의 `data_dir` 로 판정하므로, cwd 가 운영 `data_dir` 안일 때만 미탐이 된다 — 실질 위험은 낮다. 근본은 CLI 쪽(빈 env 를 `.` 로 받는 것)이고 가드 범위 밖이지만, 「CLI 와 같은 순서」를 약속한 이상 적어 둔다. `RCM_CONFIG=` 빈 값은 CLI 도 `if env:` 로 무시하므로(config.py 394~395행) 거기선 일치한다.
- **B-2. 다른 `RCM_SERVER_*` 덮어쓰기는 보지 않아도 된다는 근거가 코드에 없다.** `_env_overrides` 는 `[server]` 의 **모든** 필드를 env 로 덮는다. DB 위치를 바꾸는 건 `data_dir` 뿐이라 `RCM_SERVER_DATA_DIR` 만 보는 게 맞지만, 그 이유(`data_dir` 이 유일한 경로 필드)가 주석에 없어 다음 사람이 `RCM_SERVER_PORT` 를 왜 안 보는지 묻게 된다. 한 줄이면 된다.
- **B-3. `env -u RCM_SERVER_DATA_DIR rcm token …`**(세션 환경의 변수를 지우는 형) — 89.md B-4 와 같은 뿌리. `_argv` 가 `-u` 를 못 떼어 판정 자체가 사라진다(None). 세션 env 에 운영 `data_dir` 이 들어 있고 그걸 벗겨 시험 설정을 쓰려는 명령이라 실제로는 안전한 방향이지만, 반대(세션 env 가 시험, `-u` 로 벗기면 설정이 운영)도 None 이다.
- **B-4. 훅 프로세스의 환경이 Bash 도구의 환경과 같다는 전제.** `os.environ.get("RCM_SERVER_DATA_DIR")` 은 훅이 받은 환경이다. Claude Code 가 훅과 Bash 도구에 같은 환경을 주는지는 **확인 못 함**(문서상 그렇다고 알지만 이 리뷰에서 검증하지 않았다). 다르면 세션 env 케이스는 그 방향으로 오탐·미탐이 난다. `RCM_CONFIG` 쪽(`main()` 632행 `local_config=bool(os.environ.get("RCM_CONFIG"))`)도 같은 전제라 새 위험은 아니다.

## C. 테스트가 잠그지 못한 것

- 돌연변이: 438행의 `or os.environ.get(…)` 제거 → **2 failed**(잡힘). 438~440행 블록 전체 제거 → 실패(#93 의 parametrize 가 잡는다). 이 PR 의 세 테스트는 자기 변경을 잘 잠근다.
- 빠진 것:
  - `--data-dir` 가 env 를 이기는 케이스는 있는데(`test_…_away_from_production_is_free` 둘째 단언), **env 가 `--config` 의 `data_dir` 을 이기는 방향으로 「시험 env + 운영 설정 → allow」** 는 있고 「운영 env + 시험 설정 → deny」 도 있다. 좋다. 없는 건 **`RCM_SERVER_DATA_DIR` 이 상대 경로**일 때(`RCM_SERVER_DATA_DIR=data rcm token …` — `_as_path` 가 cwd 기준으로 푼다; cwd 가 `/srv/rcm` 이면 deny 여야 한다).
  - B-1 의 빈 값. 결정을 어느 쪽으로 하든 테스트로 고정할 가치가 있다.
  - `env VAR=… -- rcm` · `env -u` 는 89.md C 와 같다.
- `test_the_data_dir_env_override_in_the_session_environment_is_seen` 은 `monkeypatch.setenv` 를 쓴다 — `decide()` 가 「순수 함수, 시계도 파일도 안 본다」(모듈 docstring 10행)는 약속과 어긋난다. 실제로는 #89 부터 `os.environ`(443행)·`config.open`(415행)·`local.exists()`(453행)·`_which`(406행) 를 본다. docstring 을 고치거나 env 를 인자로 넘기는 편이 정직하다(P2, 89.md 의 `_config_data_dir` 부터 같은 문제).
