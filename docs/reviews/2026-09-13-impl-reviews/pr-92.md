## B. 버그 · 오류 경로 · 보안

**종료 코드 보존 — 확인됨.** 손으로 돌린 결과: 명령이 7 → 래퍼 7, 없는 명령 127(테스트), `kill -TERM $$` → **143**(신호도 보존). `tee`·`sed`·`awk` 의 종료 코드는 어디에도 섞이지 않는다(`exit "$rc"`, 76행).

**임의 출력 파싱 안 함 — 확인됨.** 래퍼는 `--pattern`(기본 `^FAIL: (.+)$`, 줄 앞 고정)에 맞는 줄만, 그것도 `rc != 0` 일 때만 이름으로 옮긴다(63행 조건). 성공한 명령의 `FAIL:` 언급은 버려진다(테스트 `test_wrapper_names_nothing_for_a_green_command`). 서버 쪽은 여전히 `::rcm::` 마커만 읽는다(`core/progress.py:parse_marker`).

1. **P2 — `--pattern` 에 `/` 가 들어가면 sed 식이 깨져 이름이 하나도 안 나온다(조용히).** `name-failures.sh:64` `sed -nE "s/$pattern/\\1/p"` 가 패턴을 `s///` 구분자 안에 그대로 끼운다. 재현: `bash examples/preset/name-failures.sh --pattern '^FAIL: test/(.+)$' -- bash -c 'echo "FAIL: test/a.dart"; exit 1'` → stderr `sed: 1: "s/^FAIL: test/(.+)$/\1/p": bad flag in substitute command: '\'`, 마커 0개, rc 1. 그룹이 없는 패턴(`'^FAIL: .+$'`)도 같은 방식으로 `\1 not defined` 로 죽는다. fail-open 은 아니지만(거짓 이름은 없고 종료 코드는 그대로) 「경로가 들어간 정확한 형식」은 이 래퍼의 가장 흔한 사용처라 조용한 실패가 곤란하다. 헤더(19~22행)는 `/` 를 언급하지 않는다. 제안: 패턴 검증을 앞에 두거나(`printf '' \| sed -nE "s/$pattern/\\1/p" \|\| { echo "bad --pattern" >&2; exit 2; }`), 구분자를 sed 가 아닌 awk `match()` 로 옮기거나, 최소한 헤더에 「`/` 는 `\/` 로」를 적는다.
2. **P2 — 120자 자르기가 awk 구현에 따라 바이트가 될 수 있다.** `name-failures.sh:66` `substr($0, 1, 120)`. macOS awk 20200816 은 문자 단위였다(한글 54자 이름 → 134바이트·54자·유효 UTF-8 로 통과 확인). Ubuntu 기본 `mawk` 는 바이트 단위다 — **확인 못 함**(이 머신에 없다). 바이트로 자르면 멀티바이트 글자 중간이 잘려 워커가 `errors="replace"` 로 읽고(`worker.py:542`) 이름 끝에 `�` 가 남는다. ASCII 이름만 쓰는 팀에는 영향 없음. 헤더의 「the same rules the server applies」는 Linux 에서 엄밀히는 틀릴 수 있다.
3. **P2 — 이름 100개를 꽉 채우면 `--step` 의 스텝 이름이 대장에서 빠진다.** 래퍼는 `head -n 100`(67행) 뒤에 `::rcm::step-end::fail` 을 찍는데, 서버는 step-end 로 오는 스텝 이름을 `len(fail_names) < MAX_FAIL_NAMES` 일 때만 붙인다(`core/progress.py:168`). 래퍼가 100개를 내면 스텝은 101번째라 대장에 안 남는다(`failed_step` 자체는 남는다). `--step` 이 있을 때 99개로 줄이거나 헤더에 적어 두면 된다. 재현 조건이 극단적이라 P2.
4. **P2 — PLAN.md CLI 예시(diff hunk @@ -433)** `job=$(jq -r .job_id <<<"$out")` 는 `rcm run` 이 제출 전에 끝나면(usage 2 · 연결 실패 3, stdout 에 JSON 없음) jq 가 stderr 에 오류를 찍고 `job` 이 비어 `*)` 분기가 `log: rcm logs ` 로 끝난다. 예시라 P2. `examples/session/ci-gate.sh` 도 같은지 확인 못 함.
5. **문제 없음 —** `WaitReason(str)`(`client.py:903`): `str` 서브클래스라 `"not found" in reason`·`_err(reason)`·JSON 모두 그대로. `copy`/pickle 에서 `cause` 가 사라지지만 쓰는 곳이 없다. `cli.py:657 getattr(reason, "cause", None)` 이라 옛 `str` 사유가 남아 있어도 안전(=로그 줄 유지, 결정 70 쪽으로 기운다).
6. **문제 없음 —** `--step NAME` 은 살균 없이 `::rcm::step::$step` 으로 나가지만(58행) 값의 주인은 프리셋 작성자이고 서버 입구 `clean_name` 이 제어문자를 지운다. 임시 파일은 `mktemp` 실패 시 exit 3.
7. **보안 —** `rcm check` 의 `local data dir … · from <config path>` 는 로컬 터미널에만 나오는 로컬 경로다(서버 상태·오류·로그 아님). 규칙 위반 아님.

## C. 테스트가 잠그지 못한 것

- `--pattern` 에 `/` 또는 그룹 없음(위 B1) — 테스트는 `^not ok [0-9]+ - (.+)$` 하나뿐.
- 비ASCII 이름의 120자 자르기(B2) — 테스트는 `x`×200.
- 신호로 죽은 명령의 종료 코드(143) — 손으로 확인했고 테스트는 없다. 한 줄이면 잠근다.
- `test_wrapper_says_what_it_relies_on` 은 `"buffer"`·`"guess"` 문자열 냄새 맡기 — 약하지만 문서 잠금으로는 충분.
- `test_docs_show_both_ways_to_name_a_failure` 는 `_section(…, "Making a failure explain itself")` 로 잡는데 `_section` 은 다음 `## ` 까지 잘라 `### Naming what failed` 가 같은 절에 포함된다(`tests/test_examples.py:174-179`). 사이에 `##` 절이 끼면 조용히 빠진다 — 지금은 문제 없음.
- mutcheck 후보: `name-failures.sh:63` 의 `if [ "$rc" -ne 0 ]` 제거(성공 명령의 언급이 이름이 된다) → `test_wrapper_names_nothing_for_a_green_command` 가 잡는다 ✓. `progress.py` 쪽 변화는 없으므로 새 mutant 는 불필요.
