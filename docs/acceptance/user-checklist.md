# 사용자 관점 체크리스트 (v0.1.0)

> 목적: 코드를 모르는 사람이 **README 만 들고** 이 도구를 쓸 때 막히는 곳·헷갈리는 곳·틀린 문구를 찾는다. 판정은 「됐다/안 됐다」가 아니라 **「처음 보는 사람이 다음 행동을 알 수 있었는가」** 다. 막힌 지점마다 「내가 뭘 봤고, 뭘 기대했고, 어디를 어떻게 고치면 되는가」를 적는다. 보고서는 `docs/acceptance/reports/<날짜>-user-<페르소나>.md`.
>
> 세 페르소나. 각자 **새 HOME**(`export HOME=$(mktemp -d)`)에서 시작하고, README 밖의 지식(코드·PLAN·docs)을 쓰지 않는다. 쓰게 됐다면 그것이 곧 발견 사항이다.
