## 막힌 순간 Top 5 (새 사용자가 포기했을 지점부터)

1. **U2.1 — 「Session machine (3 commands)」를 그대로 하면 `rcm run ok` 가 홈 디렉터리 전체를 올리고 실패한다.** `snapshot: 980 files · 6.1 MB` → `failed · snapshot rejected: absolute link target in archive` exit 1. README 의 "first job … means everything works" 가 첫 시도에서 거짓이 된다. 프로젝트의 자체 smoke 스크립트조차 `cd "$WORK/project"` 를 먼저 한다. 고침: README 블록에 `cd` 한 줄 + 클라이언트가 절대경로 심볼릭 링크를 걸러 주거나 파일명을 말해 주기.
2. **U3.6 — 폰에서 내 대기 잡을 취소할 수 없다.** 대기 행에는 Cancel 도 펼침도 없고, 탭해도 반응이 없다. README 는 토큰을 넣으면 cancel 이 된다고 한다. 유일한 우회는 `rcm cancel N`(README 에 그렇게 적혀 있지도 않다).
3. **U2.9 — 서버가 꺼졌을 때 `rcm eta`·`rcm jobs` 가 아무 말 없이 exit 3, `rcm wait` 는 60초 동안 아무 출력이 없다.** 스크립트에서 쓰면 "왜 3이지?" 를 알 길이 없다. `rcm top` 처럼 `cannot reach <url>` 한 줄이면 된다.
4. **U4.1 — README Install 첫 줄 `pipx install remote-ci-monitor` 가 PyPI 404.** "before the first PyPI release" 주석은 셋째 줄에 붙어 있어 첫 줄이 되는 줄 알고 시도하게 된다. 둘째 줄 `uvx` 도 uv 설치법이 없다.
5. **U1.4 · U4.3 · U1.13 — README 가 안 알려주는 것들을 `--help` 로 찾아야 했다.** admin 토큰(`--admin`) · `rcm token list` · `--port` · `.rcmignore` 문법과 `--exclude` · `--by`/`--no-join`/`--dir`/`--timeout` · `rcm check --config` · 업그레이드/재시작 절차. 하나하나는 작지만 관리자 페르소나가 매번 `--help` 를 열게 만든다.

## 문구·문서 수정 제안 (그대로 붙일 수 있게 before → after)

1. **README 「Session machine (3 commands)」**
   before:
   ```
   rcm run ok                 # first job: exit 0 and one JSON line means everything works
   ```
   after:
   ```
   cd ~/src/app               # any project directory — rcm run uploads the *current directory*
   rcm run ok                 # first job: exit 0 and one JSON line means everything works
   ```
   (스모크 스크립트의 `smoke:begin/end` 대조 규칙 때문에 `cd` 줄은 `rcm` 으로 시작하지 않아 검사 대상이 아니다.)
2. **README 「Install」** — 순서와 주석:
   before: `pipx install remote-ci-monitor                      # from PyPI` (첫 줄) … `pipx install git+https://github.com/monocsp/remote_ci_monitor   # from git (main); add @dev for the dev branch — use this before the first PyPI release`
   after: git 줄을 첫 줄로 올리고 `# from git (main) — the way to install until the first PyPI release; add @dev for the dev branch`, PyPI 줄은 `# from PyPI (not published yet — see Releasing)`, uvx 줄 뒤에 `# uv: https://docs.astral.sh/uv/getting-started/installation/`.
3. **README 「Build machine (3 commands)」** 블록 아래 문단 끝에 추가:
   `Tokens: `rcm token add ops --admin` makes an admin token (pause/resume, cancel any job, read any log); `rcm token list` never shows secrets; `rcm token revoke NAME`. Another port: `rcm serve --port 8790` (or `port = …` in server.toml).`
4. **README 「Session commands」 표**
   before: `` `rcm run PRESET [-f k=v] [--ref REF] [--no-wait] [--poll]` ``
   after: `` `rcm run PRESET [-f k=v] [--ref REF] [--by LABEL] [--no-join] [--no-wait] [--exclude PATTERN] [--dir DIR] [--timeout S] [--poll]` `` — 설명 끝에 "`--no-join` never joins an identical job; `--exclude` adds an `.rcmignore` pattern; `--dir` snapshots another directory".
   `` `rcm eta PRESET [-f k=v]` / `rcm eta --job N` `` → 뒤에 `[--json]`; `` `rcm jobs [--mine] [--state S]` `` → `[--json]`; `` `rcm presets` `` → `[--json]`. 표 아래 한 줄: "`rcm check --config server.toml` validates a server config without starting it."
5. **README `rcm run` 문단**
   before: `` `rcm run` snapshots the current directory (git-tracked + untracked-but-not-ignored files, minus `.rcmignore`), uploads it … ``
   after: `` `rcm run` snapshots the **current directory** (git-tracked + untracked-but-not-ignored files, minus patterns in `.rcmignore` — gitignore syntax, e.g. `dist/`, `*.bin`; `--exclude PATTERN` adds one). The server refuses snapshots above `max_snapshot_bytes` (default 512 MB) before anything is uploaded. Symlinks that point outside the tree (absolute targets, e.g. a venv's `bin/python`) are rejected — exclude them. The workspace on the build machine has **no `.git`**; scripts that need git history belong in a `git_ref` preset. ``
6. **README 「Exit codes」** 표 아래:
   before: `Usage errors and validation failures that never reach the server exit with 2 as well.`
   after: `Usage errors and validation failures that never reach the server exit with 2 as well — including `rcm run` when the server cannot be reached before submit. `rcm wait` gives an unreachable server 60 s to come back (printing `reconnecting…`) before exiting 3.` (클라이언트도 그에 맞춰 `rcm eta`·`rcm jobs` 에 `rcm: cannot reach <url>: …` 를 찍는다.)

- **재시작 의미론**이 README 「Verify」와 정확히 일치: INT/TERM 은 스크립트까지 끝내고 `lost · server stopped while running`, `kill -9` 는 `recovered on start: lost=[8]` 로 표시하고 대기 잡은 그대로 돈다. 업그레이드 뒤에도 큐와 정지 상태가 남는다.
- **첫 화면 세 카드**(YOUR JOBS / NOT MOVING / HOST PRESSURE)가 500 px 폰에서 스크롤 없이 답하고, 대기 사유가 한 줄(`waiting for lane · 1/1 busy · behind #26 · frees in 7m 51s`)로 읽힌다.
- **Lost connection 띠**의 문구 "showing last known state" 와 "last known:" 접두, 화면을 흐리지 않고 나이를 계속 세는 것, 재시작 뒤 저절로 사라지는 것. `stale 21s` 배지와 띠가 다른 상황을 다르게 말한다.
- **토큰 대화상자** 문구("It stays in this browser only and unlocks your jobs, log tails, logs and cancel") · 틀리면 붉은 `Token rejected` · 맞으면 이름과 `you` 배지 · 남의 잡의 Log 는 행 안에서 "not your job".
- **Log 서랍이 URL(`#/jobs/N/log`)** 이라 뒤로가기·Escape·딥링크가 모두 자연스럽다. 포커스 링이 모든 요소에 보인다.
