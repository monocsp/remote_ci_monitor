## 비고 (오류는 아니지만 다음 사람이 알아야 할 것)

1. **`/api/health` 는 `read_auth = "basic"` 에서도 토큰 없이 200 이다.** wheel 은 401 이 맞게 나오고(V4.4), health 가 열린 것은 #90 이전부터의 설계(liveness)라 V4 표의 기대에 어긋나지 않는다. 다만 basic 서버에서 `client_wheel.sha256`·`version` 이 토큰 없이 읽힌다는 것은 알아 둘 것 — 코드 자체는 공개 저장소라 새 노출은 아니다.
2. **`joined` 는 기다린 뒤의 JSON 에는 합류했을 때만 실린다.** `--no-wait` 출력에는 언제나 있다(`false` 포함). 래퍼가 「기다린 뒤 JSON」에서 `joined` 를 읽는다면 `jq -r '.joined // false'` 처럼 없음을 `false` 로 읽어야 한다. 옛 클라(0.2.4)도 같은 규칙이라 교차 버전 차이는 아니다.
3. **옛 서버 앞의 새 클라는 `newer` warn 이다.** `rcm check` exit 0 이고 `rcm run` 은 아무 말 없이 돈다 — 옛 서버가 `min_client_version` 을 안 주므로 「너무 새롭다」는 판정은 없다(서버가 실제로 거부하면 그때 400).
4. **래퍼의 실패 종료 코드는 단계마다 다르다**: 2(venv 의 python 없음) · 3(서버가 wheel 을 안 준다) · 4(sha256 불일치) · 5(설치 뒤 버전 불일치) · curl 의 22 등은 그대로 전달(`set -e`). 「종료 코드 보존」은 성립하지만 호출 쪽이 코드 값을 분기하려면 스크립트 머리말의 숫자를 문서에 옮겨 적을 만하다(P3).
