## 3. 비고 (오류는 아니지만 적어 둔다)

- **`min_client_version` 이 빌드 버전보다 높다(0.2.7 > 0.2.6).** 키를 켠 8804 에 같은 빌드의 `rcm run` 도 `warning: this client v0.2.6 is older than the server accepts (min_client_version 0.2.7)` 를 찍는다(G5.6 stderr 첫 줄). PR 이 「알려진 것」으로 적은 대로 0.2.7 릴리스에서 사라진다. 릴리스 전에 키를 켜는 운영자는 이 경고를 보게 된다.
- **상태 파일 lookup 의 폴백.** `submissions.lookup` 은 「내 토큰 지문의 항목 → `cancel_job` → 최근 것」 순이라, 같은 OS 사용자의 **다른 토큰** 세션이 그 잡에 항목이 없으면 요청자의 `cancel_job` 비밀을 집어 보낸다(G5.10 첫 시도에서 비-admin `root --admin` 토큰이 alice 의 비밀로 잡을 취소한 것이 이 경로). 상태 파일은 그 OS 사용자의 것이고 서버 경계(다른 머신·세션이 같은 토큰을 나눠 쓰는 경우)는 그대로이므로 오류로 보지 않았다 — 지문이 다르면 폴백하지 않게 할지는 오너 판단(§4).
- **G5.20 의 백업 옆 파일.** 성공한 경계 백업 옆에 `rcm.sqlite3.v16.bak-wal`·`-shm` 이 남는다(검증 연결이 WAL 로 연 흔적). 복구 시 `.bak` 만 쓰면 되고 해롭지 않다.
- **서버는 요청 줄을 로그에 남기지 않는다.** G5.14 의 「서버 로그에 cancel 요청 없음」은 로그 문자열이 아니라 잡이 `running` 으로 남고 표가 불변인 것으로 확인했다.
- 옛 서버(8805)의 v16 픽스처에서 running 이던 잡 #2 는 서버를 내릴 때 `lost` 가 됐고, queued 였던 #3 이 새 빌드에서 곧바로 실행됐다(G5.19 의 「옛 잡 admin 취소」는 그 #3).

## 4. 오너 판단이 필요한 것

1. **G5.23 — `"yes"`·`"1"` 을 받는 것.** 로더가 모든 bool 키에 문자열 `"1"/"true"/"yes"/"on"` 을 허용한다(환경변수용). 시나리오는 이 키만 exit 2 를 기대했다. PR 의 판단(공통 규칙 유지)을 그대로 두는가.
2. **G5.22 — admin 의 웹 취소 범위.** 명세 문구 「admin 토큰이 아닌 한 비활성」과 문서(`docs/configuration.md` 「disabled unless the pasted token is an admin token」)는 admin 이면 열린다고 읽히지만, 웹은 PR 이전부터 **내 잡**(요청자·합류자)에만 버튼을 그린다. 키와 무관하게 admin 이 남의 잡을 웹에서 취소하는 것은 지금도 안 된다(API 는 된다). 그대로 두고 문서 문구를 「admin 의 자기 잡」으로 좁힐지, 웹에 admin 취소를 열지.
3. **§3 의 상태 파일 폴백** — 다른 토큰 지문의 `cancel_job` 항목까지 집을지.
4. **bearer 토큰도 `-` 로 시작할 수 있다** — `rcm token add` 의 `token_urlsafe(32)`(§2 비고). PR 이전부터의 일이라 여기서 고치지 않았다. 같은 방식(다시 뽑기)으로 고칠지.
5. **릴리스 전 키 on** — `__version__` 이 0.2.7 이 되기 전에 키를 켜면 같은 빌드도 경고를 찍는다(§3). 0.2.7 릴리스와 함께 켜는 것을 운영 문서에 적을지.
