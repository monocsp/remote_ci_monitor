## 비고

1. **정상 PATH 에서는 맨 `rcm` 이 언제나 서비스 자신이다** — L4.6~L4.10 의 deny 기대는 PATH 의 `rcm` 이 워크트리 빌드인 전제(리뷰 #89 의 픽스처)라 WP 로 돌렸다. NP 에서 같은 명령이 allow 인 것은 면제가 맞게 도는 것이다(L4.3).
2. **명세의 `prod-checkout` 은 `git worktree add` 로 만들라 했지만** 그러면 `.git` 이 파일이라 가드가(맞게) 후보에서 뺀다 — 실제 운영 체크아웃 모양(`.git` 디렉터리)으로 `git init` + fetch 로 만들었다. 명세를 따랐다면 L4.2 는 `venv=None` 으로 「오류」처럼 보였을 것이다.
3. **`/usr/bin/python3`(3.9) 로 훅을 돌리면 `tomllib` 이 없어** `_config_data_dir` 이 None → 설정 사본 판정(L4.4·L4.7)이 사라진다. `.claude/settings.json` 이 어느 `python3` 를 잡는지는 세션 PATH 에 달렸다 — 이 Mac 은 `/opt/homebrew/bin/python3` 가 앞이라 3.11 이다. 명세 밖이라 기록만.
4. L4.10 의 수정으로 발견은 XDG 를 안 보지만 **판정**(`_effective_data_dir`)은 여전히 CLI 순서대로 `$XDG_CONFIG_HOME/rcm/server.toml` 을 본다 — 세션 XDG 의 시험 설정은 allow, 그 세션에서 운영을 직접 가리키면 deny(표의 L4.10 실측).
